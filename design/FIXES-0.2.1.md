# 0.2.1 控件与字体修复

保持整句字帖的布局。本轮只修复交互、悬停提示和字体目录；没有重新设计主界面，也没有新增宣传文案。

## 可复现问题与修复

- 原生点击设置、图钉、缩小图标后，页面/置顶状态/字号均不变化，而文字按钮正常。GPUIX Solid 0.10 的 Tooltip Trigger 使用 `asChild` 时，直接覆盖子元素事件。现将按钮完整事件交给最终的 Trigger 绑定；一次点击只触发一次动作，键盘处理也保留。
- 开关中间的白色圆点覆盖了点击区域。将纯装饰圆点设为不接收鼠标事件，中心点击可以切换开关。
- Tooltip 圆角背后出现黑色三角。原生 anchored 容器带默认方形深色填充；只给子元素设置浅色圆角会露出底板。将背景、描边和圆角统一画在 anchored 容器上，移除多余表层，提示本身不挡住操作。
- 观察到字体列表有时仅含三种内置字体；系统的只读枚举能列出数百种字体。未能确定原 Bun FFI 回调路径偶发失败的底层原因，已移除该路径。枚举现由 Rust 的有类型 Windows API 完成，通过一次性 `--list-fonts` JSON 命令传回，前端异步加载并在打开列表时刷新；失败会显示重试入口，不再静默当成完整目录。

## 验证范围

- TypeScript 类型检查与 Rust / Windows 便携构建通过。
- 检查使用与正式版本同源、相同 minify/compile 选项的 EXE。仅检查开关不同：固定在整个虚拟桌面外运行、禁止激活、不启动输入监控、不保存检查数据。
- 通过真实控件的原生点击路径核对完成输入、设置、双字体开关、返回、图钉、缩小/放大、点字看笔顺、下一个字、收起笔顺、字体搜索和选择。没有用直接设置业务状态冒充按钮成功。
- 字体目录包含系统字体；输入 `arial` 后选择 Arial，再切回霞鹜文楷。
- 取悬停后的原生 PNG，对照四个圆角；同时检查浅色、深色与提示关闭后的画面。
- 最终编译检查连续三轮通过，每轮 16 项；包含键盘触发仅执行一次、提示显示时仍能点中按钮。三轮浅色提示四角像素均为背景/边缘浅色（最低通道值 244），没有旧版的深色底板。
- 本机检查目录为 530 个字体选项；字体查询独立命令得到 529 个系统字体族，界面另外并入内置字体并去重。退出图标也通过实际点击关闭了隔离 EXE。
- 本目录证据：`v021-tooltip-light.png`、`v021-tooltip-dark.png`、`v021-system-font-search.png`。
- 只修控件，不追加三轮视觉改版评分。保留原来的动效。

没有操纵真实桌面的输入法、鼠标或键盘；CSP/KalaPaint 自动唤起仍沿用 0.2.0 的待验收状态。图钉检查覆盖按钮到状态变化，不将隔离窗口的检查当作用户桌面上的置顶验收。隐藏、退出和穿透只可在本任务的隔离实例内检查，不影响用户打开的应用。

Logo 的偏好参考尚未收到，因此本版保留原图标，待参考明确后单独更新。
